# Contributing to Dermatology Clinic Project

Thank you for being part of our development team! To maintain a high-quality codebase and smooth collaboration, please follow these guidelines.

## 🌿 Branching Strategy
- **Main Branch**: Only contains stable, production-ready code.
- **Development Branch (`dev`)**: The main integration branch.
- **Feature Branches**: Create a branch for every new feature or bug fix.
  - Format: `feature/your-feature-name` or `bugfix/issue-description`.

## 💻 Workflow
1. **Pull latest changes** from `dev`.
2. **Create a branch** for your task.
3. **Commit often** with descriptive messages (e.g., `feat: add patient appointment history`).
4. **Push your branch** to the repository.
5. **Open a Pull Request (PR)** against the `dev` branch.
6. **Request a review** from at least one teammate.

## 🛠️ Code Standards

### Frontend (TypeScript / React Native)
- Use functional components and hooks.
- Follow the existing folder structure in `app/` and `components/`.
- Use TypeScript interfaces for all data structures.
- Format code using Prettier.

### Backend (.NET API)
- Follow the Repository Pattern used in the project.
- Use meaningful names for Controllers and Models.
- Ensure all new API endpoints are documented (Swagger).
- Handle errors gracefully with appropriate HTTP status codes.

## 📝 Commit Messages
We follow a simple convention for commit messages:
- `feat:` for new features.
- `fix:` for bug fixes.
- `docs:` for documentation updates.
- `refactor:` for code improvements without feature changes.

## 🚀 Getting Help
If you run into issues or have questions about the logic:
- Contact the Lead Developer.
- Open an **Issue** on the GitHub repository with the `question` label.
